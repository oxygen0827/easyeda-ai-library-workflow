# VibeHard · 嘉立创EDA AI 建库工作流

**从芯片手册到可放入原理图和 PCB 的器件：可复现样例、操作教程与问题记录。**

本仓库以 **TPS54331DR / D封装 / SOIC-8** 为例，整理了“手册 → Symbol → Footprint → Device → 工程放置 → PCB转换”的完整实测资料。目标是让新器件接入更便捷，同时让引脚、封装和来源可以核对。

当前是 **工作流验证与样例仓库**，尚未交付一个支持任意芯片的一键建库工具。AI提取使用[嘉立创官方 AI智能建库扩展](https://github.com/easyeda/eext-ai-library-builder)；我们的工作是流程串联、变体核对、参数修正、原生交付与证据整理。本仓库没有修改官方扩展，也不隶属于嘉立创官方。

> 本次原始实测已完成：8脚符号、封装关联、原理图U1放置，以及向PCB转换后的8焊盘核验。需要人工修正，封装丝印仍压住焊盘，**样例尚未通过生产审核**。公开副本移除了作者账号元数据，其重新导入/打开尚未实测。[完整结果](docs/trial-report.md)

## 与嘉立创官方流程有什么区别？

首先区分两个经常被混用的概念：

- **导入已有库**：你已经有符号、封装或器件包，把这些数据导入嘉立创EDA。导入器负责载入已有数据，并不会凭空从PDF生成新器件。
- **从零创建新器件**：你只有手册，需要获得符号、封装并建立器件关联，之后才能放置。AI辅助主要帮助这一段。

官方已经提供手动绘制、符号向导、现有库复用、批量创建和AI扩展，不能把官方流程概括成“只能逐脚手画”。其器件机制允许关联符号、封装和可选3D模型；本样例没有3D模型。[官方创建器件文档](https://prodocs.lceda.cn/cn/device/file-new-device/)、[官方快速入门](https://prodocs.lceda.cn/cn/quick-start.html)

| 环节 | 官方常规建库/导入 | 官方AI扩展 | 本仓库目前提供 | 我们后续要自动化的部分 |
| --- | --- | --- | --- | --- |
| 输入 | 已有库，或工程师整理的引脚与尺寸 | PDF/图片 | 完整型号、封装后缀与对应手册页 | 自动定位资料，集中确认目标变体 |
| 符号 | 复用、手画或向导生成 | 识别引脚并生成图形 | 8脚实测样例、纠错记录和电气类型表 | 脚数/编号/电气类型检查 |
| 封装 | 复用、绘制或参数工具 | 识别尺寸并按模板生成 | 机械尺寸与推荐焊盘的区分、修正前后数值 | 确定性模板与完整几何检查 |
| 器件关联 | 在原生界面关联；批量创建可按同名库自动匹配 | 本次仍单独操作 | 手动关联步骤与原生器件包 | 自动创建Device和编号映射 |
| 工程使用 | 库中放置，再更新到PCB | 不等于自动完成整段流程 | 可打开的工程、原生转换结果和API证据 | 审核后自动入库、放置及更新 |
| 审核 | 工程师按手册检查 | 模型结果需要复核 | 每一步的已验证/待验证边界 | 统一预览、差异提示和版本化审核 |

### 我们的优势体现在哪里？

**现在已经提供的价值：**

1. **一次拿到完整案例。** 不只有生成的图，还包含手册页、原生器件包、工程和核验数据，可沿同一条路径学习、检查和复用。
2. **先确认型号变体。** 本例明确区分D/SOIC8和DDA/PowerPAD，记录了混入第9脚的问题，避免把同系列不同封装混在一起。
3. **区分“能画出来”和“尺寸有依据”。** 记录了默认焊盘与厂家推荐焊盘的差异，不以“创建成功”或95%置信度作为验收结论。
4. **交付仍是原生格式。** 结果沿用嘉立创EDA的库、器件关联及工程机制，不引入另一套编辑器格式。
5. **支持按需积累。** 这个样例可以在不先下载全量官方库的情况下完成；后续可优先复用已有封装，再补充真正缺失的器件。

**计划形成的产品优势：** 将多窗口建库操作收敛为“选手册 → 确认型号/封装 → 审核一次 → 入库并放置”。这部分平台集成、自动关联、自动校验与审核发布尚未实现，不能视为当前功能。我们没有做耗时对照实验，不承诺节省比例或任意器件成功率。

## 方式一：打开已有样例，无需调用模型

1. 在嘉立创EDA中选择`文件 → 打开工程`。
2. 选择以下目录内的同名`.eprj3`文件。**保留整个文件夹**，不要只复制入口文件；符号、原理图和PCB数据还在旁边的子目录中。

   ```text
   VibeHard_AI_Library_Trial_TPS54331DR_20261111/
     VibeHard_AI_Library_Trial_TPS54331DR_20261111.eprj3
     sch/Schematic1/P1.esch2
     pcb/PCB1.epcb2
     ...
   ```

3. 在`Board1 → Schematic1 → P1`查看U1的8脚符号，在`PCB1`查看编号1–8的焊盘。
4. 对照[实测记录](docs/trial-report.md)和手册第35页检查封装；丝印覆盖焊盘是保留的已知问题，需要修正后再进入工程审核。

这是单器件放置演示，没有外围电路、板框、走线或焊接验证。公开副本完成了文件和结构校验，尚未执行客户端重新打开验收；如出现兼容问题，请记录客户端版本与报错。

## 方式二：导入已有器件包

这里走的就是嘉立创**官方原生导入流程**，不是再次AI生成。

1. 在客户端准备一个独立本地测试库。
2. 进入`文件 → 导入 → 嘉立创EDA（专业版）`，选择根目录的`TPS54331DR_AI_TRIAL.elibz2`。不同版本菜单名称可能略有差异；按导入对话框选择目标库并确认。参考[官方库相关说明](https://prodocs.lceda.cn/cn/faq/library/)。
3. 在底部器件库中找到`TPS54331DR_AI_TRIAL`，检查符号和封装预览。该包元数据包含1个Device、1个Symbol和1个Footprint。
4. 打开自己的**测试**原理图，从器件库放置该Device。
5. 检查器件属性：封装为`TPS54331DR_SOIC8_AI_TRIAL`，`转到PCB`为是。然后选择`设计 → 更新/转换原理图到PCB`，检查导入列表并`应用修改`。

原始实测完成的是“创建库后放置与转换”，导出包只做过CRC和内容校验，**本次未重新执行该包的导入试验**。导入后请实际核对结果。已有工程可能优先使用工程库中的旧模板，修改外部库后还需在工程里更新库；不能仅凭同名判断更新已经生效。[官方工程库说明](https://prodocs.lceda.cn/cn/faq/editor/)

## 方式三：从手册重新建库

### 1. 安装官方扩展

在`高级 → 扩展管理器 → 导入`选择根目录的`ai-library-builder_v2.9.2_zh-cn.eext`，启用扩展、顶部菜单与外部交互。部分版本入口在设置菜单。该安装包未经修改，来源和校验值见[第三方说明](THIRD_PARTY_NOTICES.md)。也可从[官方仓库](https://github.com/easyeda/eext-ai-library-builder)获取新版本；本例问题记录仅对应实测版本。

### 2. 配置DeepSeek

进入符号或封装编辑器，打开`智能建库 → 创建符号/创建封装 → 设置`。选择自定义、OpenAI兼容格式：

| 字段 | 本例配置 |
| --- | --- |
| API地址（完整请求URL） | `https://api.deepseek.com/chat/completions` |
| 模型 | `deepseek-flash` |
| 请求 | `POST`，`Content-Type: application/json` |
| 认证 | `Authorization: Bearer <你的API密钥>`，由扩展根据密钥框生成 |
| 图像格式 | Chat Completions `messages[].content[]`中的`image_url` |

密钥只填在扩展内并保存，不放入Git、截图、问题反馈或手册。识别会把选用的手册图像发给所配置的服务；本例使用公开手册。此配置在2026-11-11真实调用成功；后续模型名和权限以[DeepSeek官方视觉文档](https://api-docs.deepseek.com/guides/vision/)为准。

### 3. 准备准确的手册页

本例目标是`TPS54331DR`，**D封装、SOIC8、无裸露焊盘**。

| 文件 | 内容 | 核对重点 |
| --- | --- | --- |
| [完整手册](TPS54331-family-SLVS839F.pdf) | SLVS839F，36页历史快照 | 同时包含D与DDA两种封装 |
| [第4页](TPS54331-pinout-page4.png) | 引脚图与功能表 | 左侧D8脚；右侧DDA增加PowerPAD |
| [第34页](TPS54331-D-mechanical-page34.png) | D封装机械尺寸 | 这是物理引脚和本体尺寸 |
| [第35页](TPS54331-D-landpattern-page35.png) | 推荐焊盘/阻焊/锡膏图 | PCB焊盘尺寸应查这一页 |

### 4. 生成并核对符号

1. `文件 → 新建 → 器件`，选择测试库，命名。简易模式会自动创建并关联空符号；专业模式需按其界面单独关联。
2. 在符号编辑器打开`智能建库 → 创建符号`，上传手册或第4页图片。
3. 使用手动框选，**先点一个角，再点另一个角**选择目标D图，再提取。整页有多个变体时，框选后仍要核对返回表。
4. 本例两次都混入了第9脚，且电气类型均为Undefined。删除PowerPAD后，按下表补齐，再创建符号并`文件 → 保存全部`。

| 编号 | 名称 | 本次设置的电气类型 |
| --- | --- | --- |
| 1 | BOOT | 输出，沿用手册功能表O；生产审核时需考虑自举电源语义 |
| 2 | VIN | 电源 |
| 3 | EN | 输入 |
| 4 | SS | 输入 |
| 5 | VSENSE | 输入 |
| 6 | COMP | 输出 |
| 7 | GND | 地 |
| 8 | PH | 输出 |

### 5. 生成与修正封装

1. `文件 → 新建 → 封装`，命名为`TPS54331DR_SOIC8_AI_TRIAL`。
2. 打开`智能建库 → 创建封装`，上传第34页，搜索位置或手动框选，再提取参数。
3. 检查类型和参数。本次SOIC8被误判为SOT23（95%），切换为SOP又遇到缺失模板、清空参数的问题。**不要把默认生成成功当作识别成功。**
4. 实际工作中，优先复用尺寸符合的SOIC8封装；若自行创建，按第35页推荐图绘制/修改。当前版本的SOP界面无法可靠补齐本例参数，可参考[手工修正规格](docs/footprint-correction.md)，或先直接查看已修正焊盘的样例。
5. 修正丝印压焊盘问题并审核后，再保存与关联。不要将本仓库保留的试验封装直接当成可投产库。

| 参数 | 原始默认生成结果（约） | 本次按手册修正后的值（约） |
| --- | --- | --- |
| 单焊盘铜尺寸 | 0.60 × 0.40 mm | 1.55 × 0.60 mm |
| 两排焊盘中心距 | 5.80 mm | 5.40 mm |
| 同排节距 | 1.27 mm | 1.27 mm |

### 6. 关联Device并放入工程

回到器件编辑器，在属性栏选择`封装 → 添加封装`，从测试库选择正确封装并关联，检查1–8编号、保存。打开原理图，从底部**器件库**放置Device，确认封装和`转到PCB`属性，再执行`设计 → 更新/转换原理图到PCB → 应用修改`。

符号和封装是Device关联的资源；“画出了符号”不等于“已经创建完整可放置的器件”。本例不需要3D模型即可验证2D放置和转换。[官方库概念与关联说明](https://prodocs.lceda.cn/cn/faq/library/)

## 文件校验

```bash
python3 scripts/verify_bundle.py
```

脚本只在本地读取文件，不访问模型或修改客户端。它核对发布文件SHA、ZIP CRC、项目日志的JSON结构，以及实测证据里的8个符号脚、8个PCB焊盘和器件关联。**通过仅表示资料自洽和下载完整，不代表客户端导入通过、DRC通过或可生产。**

## 已知限制与后续方向

目前只验证一个器件。没有全量官方库镜像、平台一键导入服务、任意封装自动生成、3D建模或生产审核流程。公开副本未重新在客户端打开/导入；未对当前更新版本扩展重新测试。

后续优先完成：必填参数缺失拦截、封装变体识别、确定性焊盘模板、丝印/焊盘检查、符号与封装编号映射、自动Device关联、统一审核预览，再接入平台按需入库流程。
